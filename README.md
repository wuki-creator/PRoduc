# PRoduc · 产品编辑器

PRoduc 是一个面向产品设计与任务编排的轻量产品编辑器原型。它把项目、任务、功能、动线、控件和界面放在同一个工作区中，并通过两个 Agent 协作完成从任务拆解到 UI 评审的流程。

## 在线运行

本项目是纯前端静态应用，不需要构建工具或后端服务。

在项目目录执行：

```bash
python -m http.server 4173
```

然后打开：

[http://127.0.0.1:4173/](http://127.0.0.1:4173/)

也可以使用任意静态文件服务器运行 `index.html`。

## 核心模块

- **项目**：管理产品项目、任务数量和项目状态。
- **任务**：定义任务目标、输入、输出和完成条件。
- **任务配置表单**：配置目标步数、任务输入、功能映射和 Agent 触发条件。
- **控件**：维护可复用的文本输入、选择器、主按钮、步骤条、状态提示等控件。
- **动线**：用操作步骤描述用户如何完成任务，并校验步骤数。
- **功能**：管理任务中的功能单元 `a`。
- **界面**：将控件组合成界面 `Q)，并执行界面组合评审。

## 两个 Agent

### 生产 Agent

生产 Agent 负责把产品目标拆解为可执行的功能和界面方案：

1. 读取任务目标和输入。
2. 选择任务所需的功能 `a1)、`a2)。
3. 组合控件形成界面 `Q)。
4. 生成一版任务函数、动线和 UI 方案。

界面中的“生成下一版”和“新建”操作会模拟生产 Agent 的输出流程。

### 评审 Agent

评审 Agent 负责检查任务是否可完成，以及界面是否达到发布标准：

- 校验动线是否满足 `t = 3)。
- 检查层级清晰度、操作可发现性、认知负担和反馈完整度。
- 计算 `score(Q))。
- 对 `Q1)、`Q2) 的组合执行 `B(Q1, Q2) -> m) 评审。
- 输出发布建议和具体修改意见。

当前界面将 `score(Q) >= 80) 作为可发布阈值。

## 算法定义

### 算法 1：任务函数与动线

任务函数：

```text
out = m(a1, a2, input)
```

其中：

- `a1)、`a2` 是功能单元。
- `input` 是用户输入。
- `out` 是任务输出。
- `m` 是功能和输入的映射函数。

动线完成条件：

```text
done = a(p1, p2, pt)
```

其中：

- `p1)、`p2)、`pt` 是操作步骤。
- `t` 是达到目标所需的操作步数。
- 当前产品要求 `t = 3)。

默认示例：

1. `p1)：输入项目名称。
2. `p2)：选择项目模板。
3. `pt)：点击创建项目。

### 算法 2：界面组合与 UI 评审

界面组合：

```text
Q(f1, f2, f3, ...)
```

其中 `f` 是控件。

界面组合评审：

```text
B(Q1, Q2) -> m
```

评审 Agent 对界面组合输出：

```text
score(Q)
```

评分维度包括：

- 层级清晰度
- 操作可发现性
- 认知负担
- 反馈完整度

## 技术说明

- 原生 HTML、CSS、JavaScript。
- 无第三方运行时依赖。
- 使用 CSS Grid 和 Flexbox 适配桌面与移动端。
- 页面数据目前保存在前端内存中，适合产品流程原型和交互验证。
- `运行双 Agent` 和 `运行 UI 评审` 会更新当前评审分数并显示 Agent 输出提示。

## 开发验证

检查 JavaScript 语法：

```bash
node --check app.js
```

启动服务后，可通过浏览器验证：

- 默认进入任务编辑器。
- 任务动线展示 3 个步骤。
- 运行评审后显示更新的 `score(Q))。
- 左侧导航可以切换项目、表单、控件、动线、功能和界面模块。
